# Codex 目标模式执行指令

你在 `969981/poko_resources` 仓库的 `2.0.1_unpack` 分支开展 Pokopia v2.0.1 全资源解包与分析。按 `PLAN.md`、`TASKS.md` 推进，不要停在仅提供研究建议；能验证的就运行、记录、提交，遇到阻碍保留日志并继续可执行任务。需要依赖或第三方工具时自行核验许可证与具体兼容性。**不要把任务计划误写为已经执行的事实。**

必须满足以下条件：

1. 不修改 `2.0.1/` 原始资源、`exefs/main`；不添加 `romfs/movie_asset/`；保留 `.github/workflows/restore.yml`。
2. 仓库内存在 .7z.001 分卷：完整解包前先验证连续性、校验和与 `7z t`；输出只进入 `_work`/本地 `UnPack`，避免二次向公共 Git 上传原版数据。
3. 先实现 M0，再分别突破 M1 (LINKDATA) 与 M2 (KT RDB/FDATA/.file)；在 `system.rdb` 与 `system.rdx` 调查完成之前，不声称 RDB 全覆盖。
4. 以小样本先行：先定档偏移/长度与字节级提取，再开放全量。解析失败的记录保留 raw bytes、flags、头部、source+offset、明确错误码。
5. 每类格式给出至少一个真实样本测试；不接受仅依据文件名/魔数推断“已全部解压”。对 KIDSOBJDB、BFBS、场景和地图，必须有来源与输出互相可查的证据链。
6. 按任务 ID 独立提交；每轮更新 `docs/2.0.1/PROGRESS.md`（提交、实际运行命令、成功/失败/未知数），并报告下一瓶颈。
7. 支持 `--dry-run`、`--limit`、`--resume`、`--output`；避免内存读入整个大型 BIN；不要强行修改 GitHub CI 让高磁盘任务在每次 push 执行。
8. 在安全的资源/时间限制下尽可能完成目标；无法在当前环境完成的真机/大盘任务，以清晰命令和验收脚本交付并标记未执行。**不要虚构成功、不要从未验证的文件结构推断已经完成。**

最终验收：有 `_meta/2.0.1` 的精确 manifest、两套可遍历可追溯的索引/提取器、KIDSOBJDB 真实样本、完整失败分类以及自动测试。模型/贴图/地图按证据级逐步推进。
