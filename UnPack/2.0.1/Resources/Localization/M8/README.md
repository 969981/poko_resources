# M8 — Native asset → localized text reference graph (Pokopia 2.0.1)

Status: **resource-specific references confirmed by native byte offsets**. This is NOT a validated scene/quest/building localization classifier.

## What is established

The source layout is based on the pinned [PokoHex `GameItemDumper.cs`](https://github.com/969981/PokoHex/blob/c71d2b73fb9d8cfe99c1067e6bfadfd19f60bf78/PokoHex.Parsing/GameItemDumper.cs), [`GameMapDumper.cs`](https://github.com/969981/PokoHex/blob/c71d2b73fb9d8cfe99c1067e6bfadfd19f60bf78/PokoHex.Parsing/GameMapDumper.cs), [`GameAbilityDumper.cs`](https://github.com/969981/PokoHex/blob/c71d2b73fb9d8cfe99c1067e6bfadfd19f60bf78/PokoHex.Parsing/GameAbilityDumper.cs), and the corresponding decoded **2.0.1 native bytes**. Source file hashes and exact field offsets are retained.

### Exact reference chains

1. **Items:** `00983.bin` (4,600 records; 68 bytes per record, version 3), `name_index = read_u16(64 + item_id*68 + 34)`. Zero means no native name reference. Nonzero values select the **row ID** of one of the nine `04645.bin`–`04653.bin` tables (3,001 rows, version 2, 32-byte row, form 0). The name index is **not necessarily equal to item_id**. Validate all nine values against `Resources/Items/Text/text_item_<lang>.txt` and the native validation SHA-256.
2. **MapParts:** `00041.bin` (4,096 variants × 16 bytes): `part_id=u16(64+variant_id*16+4)`, `model_id=u16(64+variant_id*16)`. Then `00040.bin` (4,096 parts × 80): `item_id=u16(64+part_id*80+6)`. Then follow the Item reference above to the locale table. `00044.bin` model shape and `00042.bin` dimensions provide independent structural bounds checking. Two independently known regression anchors are `variant 1498 -> item 1357` and `variant 3197 -> item 1628`.
3. **Reactions:** `02332.bin`–`02340.bin`, 128-row tables; in the pinned `GameAbilityDumper`, native row ID is the reaction ID.
4. **Skills:** `04942.bin`–`04950.bin`, 61-row tables; native row ID is the skill-name ID in the pinned parser.

For both 3 and 4, the empty/nonempty row layout is identical across all nine languages, but **the raw 32-bit metadata/flag fields may legitimately differ between languages**. M7's generic strict metadata-equality heuristic can exclude these groups. M8 joins them based on an explicit version-pinned native parser mapping, preserving each language's original flags.

**MapPart does not mean Building.** A valid relation to an Item does not identify a standalone construction, crafting recipe, NPC, quest, tutorial or scene. All such category assignments remain unavailable without stronger reference evidence.

## Outputs (generated by successful Actions run)

- `native_item_text_refs.csv/json`: every Item ID, native name index, exact field offset, nine language values and language-specific text offsets. Empty slots are retained.
- `map_part_item_name_refs.csv/json`: map variant → part ID → Item ID → name row, with all intermediary native field offsets, shape/dimensions and evidence grade.
- `native_role_text_refs.csv/json`: Reaction/Skill table row IDs, nine languages, per-language byte offsets and raw flags.
- `native_source_hashes.csv`: SHA-256 and exact paths for each native source used.
- `m8_report.json`: actual counts, evidence limits, and unresolved caller-reference areas.

## Next evidence needed before Quest / Dialogue / Buildings / UI classification

Find an actual caller `scene/mission/object/script/resource → text-group resource identity → native table entry (or name-index) → record ID`. Source file names or lexical matches in the text are **not** sufficient evidence. The future classifier should include the caller's raw file path, hash, member path, field offset, expected type, table ID, row ID, and reproducible code/execution references. Until such a chain exists, those categories must remain `UNKNOWN`, not fabricated.

There are two separate identity spaces: the `M7 text_id` is a **zero-based row ID inside a particular native table**, whereas item IDs, map variation IDs, part IDs and scene/mission identifiers belong to other domains.
